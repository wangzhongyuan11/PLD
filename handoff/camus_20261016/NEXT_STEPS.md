# CAMUS 优化进度与下一步

## 最近一步完成了什么

以 `56066b8` 的 20 图 PS 优化采用版为基线，当前候选增加：

1. 在现有 bank 约束下搜索非 2 的幂的 tile 尺寸，并缓存计划。拼接 tile 112→89，卷积 tile 164→158，总命令 605→547，传输字节 33,273,648→32,153,584。
2. 池化/拼接也直接写回整层输出，减少临时 tile 数组与第二次复制。
3. 只填充 RX 输出之后的尾部保护；原生 C 一次完成完整尾部检查和 scatter。RX 缓存同步及任务号、帧号、长度、超时检查保留。
4. 原生 C 在一次像素遍历中生成四张视图；叠加仍使用与原公式完全一致的查表，PNG 继续为双线程 Sub/RLE level 1 无损编码。
5. 原生 C 预处理保持原 float32 归一化、先纵后横插值、float64 最近偶数输入量化；没有替换为近似图像库缩放。
6. 每个命令额外记录 flush、native packet 和 invalidate 时间，便于后续分析。

修改范围为 `camus/` 下 11 个源文件/测试文件，不含 RTL。主机当时 44 项测试通过（原生类在 Windows 跳过），板端原生类 6 项通过，候选 3 张图的完整 HTTP/ZIP 检查通过。主机收尾复核以交付包 `evidence/offline_tests.log` 为准。

## 网络阶段还能怎样压缩

当前 engine 仍约 1.104 秒。最新候选 engine 为 110,396,848 周期，减少的主要是 tile 固定开销；模型 MAC 计算没有减少。现有逐字节装载/输出通路约 32.15 MB，100 MHz 下串行下限仍约 1.43 秒。这一数值是结构估算，不是端到端成绩。

先前 profile 候选热态一帧（559 命令、尚未采用新的卷积 tile）测得：

| 类别 | 命令累计 | flush | native packet wall | invalidate |
|---|---:|---:|---:|---:|
| 输入加载 267 次 | 0.634 | 0.111 | 0.244 | 0.001 |
| RUN/输出 267 次 | 1.698 | 0.098 | 1.274 | 0.089 |

RUN 包含 PL 计算等待。flush/packet/invalidate 是命令内部计时，不要再次加到命令累计上；这些数据来自 profile 版本，不能冒充 547 命令最终候选的精确拆分。

已经试过 RX 不可缓存分配，3 张图数值通过，但热态网络升至约 2.91–2.98 秒，慢于可缓存 RX，已撤回。不要直接重复采用。

可继续评估双 TX 缓冲：CPU 在当前 tile 的 PL RUN 等待期间准备下一 tile，但 DMA 仍单拥有者，LOAD/RUN 的 PL 串行约束仍在。要独立分配缓冲、在释放前 join 所有准备任务、保留错误恢复，并检查内存带宽争用是否抵消收益。该方案**尚未实现**。

## 阶段重叠的边界

- 同帧的输入量化、网络、四通道恢复和标签依赖有明确先后，不能把阶段时间简单相减。
- head.bin/head.json 写入可以在网络结束后与恢复/后处理重叠；处理后的 NPZ 保存可与 PNG 编码重叠。必须有界线程、全部 join、传播失败，完成后才发布 ZIP。
- 原始标签 PNG 可以在恢复完成后与后处理重叠。当前原生四视图统一渲染已经减少渲染时间，应实测拆开后的线程成本，避免反向退化。
- 单帧 PNG/ZIP 完成前不能向用户宣称“全流程完成”；只提前显示预览不构成 3 秒 ZIP 验收。
- 跨帧流水可能提高吞吐，但不自动缩短单帧上传至 ZIP 的延迟，且现有网页只接收单任务。

这些重叠方案尚未实现。当前候选仍按阶段顺序执行，PNG 内部为两个已 join 的线程。

## 接手后的最短验证顺序

1. 离线验证 `MANIFEST.json` 和运行包内 manifest；核对源文件、bit/hwh/XSA、模型哈希。
2. 有板卡后先查询当前服务/所有者，记录实际目录与 drop-in；不能把本交接的上次状态当作当前状态。
3. 按用户预算先验证最新候选同组 20 图，得到新的完整基线；比较 input/head/labels/四 PNG 像素及 ZIP CRC。
4. 先做 compact JSON、NPZ level 1；再依据实际阶段计时决定保存重叠或双 TX 准备是否值得。
5. 3 秒目标按真实 HTTP POST 上传到 ZIP 可下载计算；同时报告首帧、热态中位数、P95、最慢及 20/20 达标数，不通过则明确保留缺口。

不要修改 RTL 或时钟来凑本轮软件目标；当前用户的范围仍是非 RTL 优化。无需恢复无关的长稳测试。
