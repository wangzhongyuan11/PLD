# 板端红色正常皮肤误报：复现与修正入口

更新：2026-10-09。用户反馈皮肤镜图像在 PYNQ-Z2 上使用时，部分其认为正常的红色皮肤被分割为目标。现已收到 C 端 PLD_Web 调用封装及 A 最终包，C 合同与 A spec 一致；尚缺实际 B 核心运行包及误判同帧原图/输出，不能裁定模型学到了颜色捷径，也不能确认部署出错。“正常/目标”的像素标签仍需可靠标注确认。

新增审查结论及复现导出版见 `docs/A23_板端脚本审查与复现导出.md`：历史 ISIC_0000003 的软件和保存板测结果全部 65,536 个 head 编码一致；新网页推理导出包可保留原始 JPG 与同帧 JSON/BIN。该历史样例不代表红色误报已修复。以下作为后续排查协议保留。

同日后续收到中央红色边缘案例（结果 ZIP，不是 B 源码），并在软件二值掩膜中完全复现；与既有开发标注比较发现 FP32 已有边界外扩、INT8 更明显。最新事实以 `docs/A24_中央红色边缘案例核验.md` 为准，误报尚未修复。

## 已核实的事实

- 交付模型做病灶分割，未完成疾病诊断分类。最终包 role_a_final 的 best.pt 实际 SHA256 与 spec 一致：f488719fe6d4d09c9b86be84d06b19d34241d6c14060b87da7bab25d1367eb77。
- 输入契约是 RGB、保持宽高比缩放至 256×256 并居中补黑、NCHW；先以 float32 除以 255，再按第一层 input_scale = 0.007874015748031496 取最近偶数并饱和至 [-127,127]。第一层图像输入实际落在 [0,127]；直接把 [0,255] 的相机字节重解释为 int8 不符合契约。
- head 输出是未经过 sigmoid 的 logits，不是概率。最终包 head.output_scale = 0.1995087721216397，q 是有符号 int8，logit = q × output_scale。
- 最终包的概率阈值 0.45 等价于 logit >= -0.20067069546215124；在其量化输出上等价于 q >= -1。已逐一检查全部 255 个合法输出编码，和 torch.float32 sigmoid 判定完全一致。这一结论只适用于该尺度与阈值；输出为累加器或概率时不能套用。
- 旧包 role_a 的 head.output_scale = 0.18516788332481085；本次只以 0.45 验算其整数映射，没有替旧包选择部署阈值。实际板端应先确认包版本及采用的阈值，再从自身 spec 计算。
- 对两包的全部 256 种 uint8 输入值验证了第一层映射；核对了完整第一层输入和 head 输出黄金向量的尺寸与 SHA256。数值证据：runs/role_a_redness_triage/reference_contract_check.json。
- 当前仓库 host 界面仍是规划，没有收到用户实际部署的 PYNQ 推理脚本。这些检查没有证明板端一致性。
- 现有训练器的颜色增强是对 RGB 全通道施加相同的亮度/对比度线性变换，不包含专门的红色背景难例采样。此事实不能证明误判的根因。

## 最小复现材料

1. 优先提供 1–3 张误判原图及对应板端二值掩膜/叠加图，保留原始像素；截图用于指出错误位置，不能替代原始输入。若是实时流，固定同一帧并记录帧号。
2. 板端实际推理脚本或 notebook，以及实际使用的模型 spec、权重来源、阈值和后处理设置。若文件在本工作区，提供路径即可。
3. 条件允许时导出同一帧的模型输入缓冲、head 原始输出、valid 掩膜；写明 shape、dtype、布局及其处于哪一数值域。不得混用累加器、量化 logits 和概率。
4. 用可靠标注分别标出真实目标、确认的正常红色区域和不确定区域；不确定区域不自动作为背景参与训练。

## 排查顺序与归因

1. 确认板端包版本，排除“新权重配旧尺度/偏置/乘子”的混搭。
2. 核对 RGB/BGR、256 letterbox 几何、归一化、第一层量化及 NCHW/DMA 排列。同一原图先对齐模型输入，不仅比较显示出来的颜色。
3. 直接回放所用包 int8/encoders_0_0/input_full.bin，与对应第一层输出及 int8/head/output_full_golden.bin 对照。黄金文件属于同一个软件量化前向；用各层 full_*_shape，而非 8×8 小 tile 的 shape。局部黄金向量通过不能代替整网回放。
4. 核对跨层尺度转换、负数有符号解释、Q24 半偶舍入、饱和，以及 head 不加 ReLU。最后才核对 sigmoid/整数阈值和 valid 屏蔽。
5. 核对掩膜叠回原图时的补边去除、坐标缩放、输入输出帧号及缓存更新，排除旧帧或坐标错位。
6. 用误判同一帧分别做 FP32 软件、INT8 软件和实际板端推理：
   - 软件 INT8 正常而板端错误：优先定位部署或显示链路，不用重新训练掩盖不一致。
   - FP32 正常而软件 INT8/板端都错误：定位量化敏感性，评估校准或量化训练；评估使用同一划分和阈值规则。
   - FP32、软件 INT8、板端一致误报：进入模型数据与损失修正。

## 确认为模型问题后的候选修正

- 补充经审查的正常红色背景“难负样本”：包括真实病灶旁红色皮肤，以及确实没有目标的皮肤镜画面。前者仍保留病灶真值；只有后者整张标为背景。病灶外裁剪可以辅助训练，但应防止裁剪尺度、补边方式形成新偏差。
- 新样本按患者/病灶和采集来源隔离训练与评价，保留不同拍摄条件。已用于选方案的图归入开发集；不触碰既有 2018 最终留出掩膜。
- 先保持轻量结构与 B/C 算子接口，比较难例采样、合理颜色变化增强、背景误报惩罚等训练候选。训练策略通常可不增加推理参数量，但每个导出仍须重新量化、验收，并用同一图检查板端。
- 同时保留真实目标中的红色外观样本，避免模型变成“红色就是背景”。不要把去红色、转灰度或去小连通块直接当成修复；它们可能损伤真实目标或微小病灶，必须单独验证。
- 阈值可以作为候选，但提高阈值通常也会减少目标像素。先固定开发集和评判规则，再评价取舍，不对误判图逐张调参后声称普遍改善。

## 验收口径

除原 dev638 的总体及面积分组 Dice 外，增加实际部署场景的独立分层结果：正常红色区域误报面积/已标注红色背景面积；无目标图的误报面积占 valid 面积、超过预设容忍量的图像比例；微小病灶召回；真实红色目标的召回。数量、标注规则、容忍量及选阈值规则在比较前固定。不靠大量空图或背景像素的“准确率”掩盖目标漏检。

只有原始输入、数值输出、真实标注和完整对照能支持修复结论；现阶段没有证据证明误报已经解决。
