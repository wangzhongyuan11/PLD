# DeepSeek 助手职责与高级工程师审查

本文件细化项目 `AGENTS.md`，仅用于本竞赛项目。选择委派内容的标准是“边界明确、可执行、可验证”；通过拆分任务，将尽量多的常规执行交给 DeepSeek，同时保留 Codex 对质量与结论的责任。

| 工作类别 | DeepSeek 可承担的执行工作 | Codex 的优化与裁定责任 | 最小验收证据 |
| --- | --- | --- | --- |
| 资料与开源资源 | 按问题检索官方文档、论文、仓库、数据；提取版本、许可、输入输出和复现条件，整理比较表 | 判断是否匹配板卡、网络结构和竞赛目标；审查原始来源及复用成本，确定采用范围 | 原始链接、版本/日期、引用位置和适配差异 |
| 环境与文件盘点 | 列项目内环境、依赖版本、文件大小、运行记录；按批准清单在项目内安装或配置 | 定位兼容性问题，选择最小依赖集，审查全局写入风险和磁盘峰值；批准范围不含私人配置 | 命令结果、版本清单、变更路径和占用 |

## 可执行的裁定规则

1. **先定义完成，再派工。** Codex 给出成功条件、可改路径、资源预算和停止条件；助手可以提出备选方案，但不能自行改变验收门槛或扩展权限。
2. **批量自动化优先。** 逐图统计、文件校验、重复日志解析应一次写脚本批量执行；不为每个文件单独调用模型。无需模型判断的几条确定性命令可由 Codex 直接运行。
3. **审查投入与后果匹配。** 清单与排版采用自动核对及抽查；代码审查关键差异并运行针对性测试；数据隔离、授权边界和模型达标结论由 Codex 逐项审查。不把整项工作重新做一遍当作监督。
4. **失败扩大检查。** 抽查失败、证据相互矛盾或结果异常时扩大检查，先定位错误来源；重复失败或需要全局判断时 Codex 接管。图片能力缺失必须回报，不能把脚本统计冒充视觉判断。
5. **守住真实证据。** 助手交付“做了什么、产物在哪、如何验证、哪里未完成”；Codex 核对后才向用户报告完成。结果未达标就记录失败和下一步，不以节省额度为由降低质量。
6. **保持监督能力。** 每批任务应能独立保存和停止；不要把无限制长任务交给助手后退出监督。额度保护通知优先于继续执行，按项目断点规则交付当前进度。
