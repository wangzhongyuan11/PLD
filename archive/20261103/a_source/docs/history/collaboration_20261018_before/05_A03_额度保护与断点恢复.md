# 额度保护与断点恢复

适用范围为本项目，用户要求在额度剩余约 7% 时启动保护。本文件规定运行流程，不代表已安装后台监控，也不代表现有训练脚本已具备全部恢复功能。

## 检查与触发

- Codex 在逻辑任务开始、长任务/大批委派前及重要阶段结束时获取额度；同一阶段相邻的低成本检查可按 `A04_复杂任务接管与低消耗监控.md` 复用新鲜读数，不把每次普通追问当成新逻辑任务。读取当前适用额度桶，优先使用按额度 ID 返回的数据；通常同时检查五小时和周窗口。每窗剩余比例为 `max(0, min(100, 100-usedPercent))`，任一相关窗口剩余 **≤7%** 立即触发。
- 额度剩余 **≤10%** 时进入预备状态：缩短批次，确认产物已阶段落盘，每批后复查；若下一阶段可能吃掉收尾余量，提前触发。7% 是启动保护的上限信号，不是继续耗到最后才保存的目标。
- 不把未知值按 0% 或 100% 处理，不混淆账户额度、上下文余量或 DeepSeek 用量。查询失败须说明；若最近值已接近阈值，先保存当前断点。账户额度可能受其他任务影响，在检查间隙变化，因此不能保证精确跨越阈值的那一刻被发现。

## 触发后的顺序

1. 告知用户读到的剩余比例和进入保护的原因。停止新实验、下载、扩大任务和新增派工；允许必要的保存、校验与交接操作。
2. 通知正在运行的 DeepSeek 保存已有产物和任务状态，在当前安全步骤完成后停止；记录已完成、未完成和异常。向正在运行的训练/下载程序发送其支持的正常停止或保存信号，不在检查点写入中强杀进程。
3. 保存可恢复状态。训练应按实际能力保存模型、优化器、调度器、混合精度状态（若使用）、轮数/步数、随机状态、数据/采样顺序、配置和代码版本；下载保留有效文件、来源清单、完成项和部分文件状态。只保存了模型权重就明确注明，不能承诺恢复到同一步。
4. 采用“临时文件写完并校验，再替换正式文件”的原子写入方式，保留上一份有效检查点；先核实磁盘余量。程序没有中途保存功能时，记录最后有效保存点及会损失的进度，不为追求无损恢复临时做高风险改造。
5. 核对保存文件能读取、关键元数据齐全、日志位置有效，以及本任务相关进程是否停止；必要时记录尚未退出的进程和原因。不要终止其他项目进程，也不在此时运行全量训练或测试。
6. 更新项目内最新断点记录，写明目标、实际结果、基线/候选状态、文件入口、已验证与未验证项、数据划分和占用、助手状态、阻塞、下一步命令及恢复限制。没有 Git 时可用相关文件哈希记录版本；不把日志原文或敏感配置整份塞进上下文。
7. 向用户交付断点文件链接，说明停止状态并结束本轮。不自行兑换额度重置、付费或另建后台任务；后续恢复先重新检查额度、文件和进程，再按断点推进。

## 平时的断点要求

- 为新的长训练/下载任务设计阶段保存和正常停止机制；把恢复格式列入任务验收，首次使用时做一次小规模中断恢复验证，避免到 7% 才发现保存不了。
- 训练按合适的轮次或时间间隔保存，下载逐文件校验；重要产物原子落盘。这能减轻意外断电造成的损失，但配额阈值本身不能预知突然断电，尚未落盘的进度仍可能丢失。
- 本文是流程要求；具体脚本是否支持无损恢复，以其代码和实际验证为准。已有修复试验缺少优化器状态这一限制，仍以 `../A02_2026-09-23_断点与下载清单.md` 的记录为准，不能因新增本规则而宣称已修复。
