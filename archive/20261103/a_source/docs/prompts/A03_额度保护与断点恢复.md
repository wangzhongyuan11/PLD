# 额度保护与断点恢复

仅适用于本项目。这里规定流程，不表示所有脚本已有自动监控/停止能力。Codex订阅额度、DeepSeek API费用和上下文余量分别记录。

## 何时检查

逻辑任务开始、长任务/大批派工前、重要阶段结束、异常或用户查询时，读取当前相关额度桶。剩余为 `clamp(100-usedPercent,0,100)`，通常检查五小时及周窗口；缺失值为未知。

同一阶段相邻低成本查询：最小剩余>20%可复用10分钟，>10%且≤20%可复用2分钟，>7%且≤10%只在同一短批内复用30秒并在批末刷新。这是已有查询的复用上限，不是额外唤醒模型的定时任务；长/高成本动作和已知其他任务快速耗额时强制刷新。

- 任一相关窗口 **≤10%**：不开始新的长阶段，缩短批次，保存并准备结束；预计无法留下收尾余量时提前保护。
- **≤7%**：立即进入保护，停止新增任务，只做必要保存、校验与交接。接近阈值又读取失败时先保护；共享额度非实时，不能保证恰好在阈值触发。
- DeepSeek 达到本批费用、工作量、重试或时间上限同样保存停止；没有计量数据不宣称费用可自动封顶。任何一方保护都不能由另一方无限续跑绕过。

## 如何停止

1. 停止新增实验/派工，通知实际负责人保存；向任务进程发送其支持的正常停止信号，在安全边界退出，不强杀检查点写入、不终止其他任务。
2. 原子保存并保留上一有效状态。训练记录模型、优化器、调度器、scaler、轮/步、随机/采样状态、配置及代码/数据身份；缺项和可能损失的进度明确写出。只有权重不能称无损恢复。
3. 核对状态文件可读、元数据、保存身份与退出/资源释放。将结果和证据路径写任务短状态，Codex更新当前断点；运行/未退出不能标停止。
4. 交付恢复入口后结束；不自动充值、兑换额度、开付费并发或另建后台唤醒。有限任务租约不能仅凭旧读数自动续期。

## 如何恢复

先刷新实时额度/预算，再核对既有授权、当前断点、输入/代码身份及无重复进程。所有相关窗口>10%且满足任务预算才恢复长阶段；额度恢复不代表旧STOP和权限可以一并清除。

只处理当前任务、原因明确且已解除的保护STOP；用户暂停、旧任务STOP、封存测试与关闭许可另有约束。同一已授权任务可直接恢复，无需重复请批；新目标、新模型轮次或越界动作仍需对应授权。让原负责人明确释放控制权后再换人。

新长任务在首次使用时做小规模保存/恢复验证。平时按阶段保存；断点格式与恢复能力以实际代码和验证为准，不因规则写了就视为已经实现。
