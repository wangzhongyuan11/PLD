# 共同主执行：分工、交接与验收

项目默认模式以 `../../AGENTS.md` 为准。本协议用于有实质模块交接的任务；小修改直接完成，不为套流程增加往返。双方是各自模块的负责人，Codex 兼任当前项目集成负责人；这不要求 Codex 逐条审批 DeepSeek 的实现动作。

## 分配工作

| 优先负责人 | 适合独立负责的结果 | 另一方介入点 |
|---|---|---|
| Codex | 文献与科研判断、实验设计、数据角色/几何/统计、INT8数学合同、复杂后端与跨模块问题 | DeepSeek 可收集一手来源、复现实验、做黑盒接口/视觉检查；关键结论用原始证据或独立参考核验 |
| DeepSeek | 确定合同后的完整工程模块、自动化工具、训练/下载/评估队列、PC界面、图表与失败样例、打包和文档 | Codex 核查合同边界、关键差异和验收证据，处理无法局部解决的科学/数值/集成问题 |
| 按实际能力选择 | 数据加载、测试、性能诊断、局部后端及UI修复 | 看本项目正确率、返工、完成时间和总消耗；不按品牌固定低估或高估，也不为了均分任务制造重复 |

同一阶段可让 DeepSeek 运行已冻结的训练队列，Codex 编写独立的发布打包器；训练依赖的源码、数据、配置和GPU归队列负责人控制。两方不得同时修改同一个文件、重启同一训练或操作同一DMA。只列实际需要的任务，不建立复杂调度系统。

## 一次交接足够的信息

使用 [A00](A00_DeepSeek派工模板.md)。长任务在现有 `runs/<任务>/` 增加一份小型 `COORDINATION.json`，已有等价记录就复用；记录任务ID、负责人/复核方、允许路径、资源、输入版本、状态及更新时间/更新人、证据和停止点。**该协调表仅由 Codex 写入**；执行方只写任务自己的 `STATUS/RESULT`。派发前 Codex 预留资源并标记 `assigned`，实际启动回执到达后记 `running`，交付记 `ready_for_review`，验收后才记 `accepted`；失败/停止记 `blocked/protected` 并核实资源释放。`planned` 没有运行所有权，不允许另一方凭状态滞后重复启动；先核对负责人和实际进程。

1. 确认现有 dsh 会话、工作目录与实际模型。用户提供的令牌仅用于连接；UI 显示友好名称不证明后端精确补丁版本。不能确认时注明“版本待证实”，不因此重复试探或新建付费会话。
2. 负责人在许可范围内自主拆分步骤、实现、测试、局部修复和保存；长程任务必须有有限终点、失败/停滞检测与可恢复状态。所谓长程能力不等于无限运行权限。
3. 共享接口、模型结构/数据划分/门槛先固定。发现必须改变时提交“原因、影响、建议与证据”，暂停依赖部分；已有用户授权内由 Codex 裁定，需要新增授权才询问用户。
4. 执行方只回传变化、产物版本、退出码、关键测试/指标、失败与未完成项；Codex 更新总断点。双方反馈以文件/证据为准，不复制对方整段分析。
5. 交接或接管先让原负责人安全停止并释放写入/进程控制权，再核对差异和最近有效状态。不得覆盖对方未提交修改；修改训练源码必须先考虑检查点的源码身份绑定。

## 验收与升级

- 常规格式、清单、文档用确定性检查及抽查；代码看关键差异、接口及针对性用例。已经由可信脚本证明且输入/代码未变的结果不全量重复。
- 数据隔离、物理坐标/量化数值、最终指标、模型替换、Release/正式部署必须由 Codex 对照独立依据逐项核验关键证据。Codex 主写这些模块时使用独立数值参考、冻结基准或他方针对性检查，不能只以同一实现生成的期望值自证。
- DeepSeek 可独立复核 Codex 的可视化、用户流程、图表/报告一致性和交付可用性；仅在能发现不同错误时增加第二视角。不是每个任务都做两遍。
- 同一原因在针对性修复后再失败一次（合计两次），或来源/指标/产物相互矛盾：停止相同尝试，保留最小复现，调整方法或移交。新证据支持新方法时可继续；权限拦截不能靠换执行者绕过。
- 原生网格FP32、INT8、软件仿真、真实板测、UI可用性和发布验证分开记录。关键结果绑定配置、数据、模型和相关执行源码；相关算法改变使缓存证据失效，不能只看文件存在就复用。

## 用量与现金成本

以既定质量验收为约束，主动最小化每项已验收成果的总成本。包括双方输入/输出、付费工具、监督与返工；不以少用某一方的额度、压短输出或便宜单价代替总成本判断。下面是默认执行要求，不需要每次另做成本分析或请批。

- **调用前只做一次轻量选择**：现有证据能回答就复用；脚本能确定完成就运行；剩余判断交给最适合的一方。小任务不派工，普通任务单方完成加自动检查，只有收益明确的独立模块才并行/互审；不为证明省钱额外跑双模型比较。
- **按难度给足推理**：确定性提取用较短输出；工程模块用正常任务强度；复杂科研/数值问题给足上下文与推理。若工具支持任务级选项可局部调整，不擅改应用全局设置。不要为了压低输出额度截断代码、必要检查或难例分析。
- **一次派工，一次完整交付**：任务包给足接口、路径、必要背景和验收，执行方自主完成实现/测试/局部修复；正常阶段合并回报，异常及时报告。纯“收到/待机/再次确认”不再触发付费往返；不反复索取相同摘要或让双方重做已有验证。必要的用户进度沟通照常进行。
- **预算先有边界**：每批限定工作量、阶段/运行上限、重试及必要的模型往返；有金额上限时遵守。未给金额不虚构预算，以有界批次推进并记账。出现无新信息的重试、成本超预期或审查比直接完成更贵时调整方法；明显扩张实验/并发/支出前说明收益与预算。
- **上下文按需读取**：先定位再读片段、差异和短状态；一次合并独立检查，避免多轮全量工具输出。稳定短前缀与增量输入可利用缓存，但命中仍有成本且不保证；旧历史妨碍判断或反复带入明显增加开销时先保存关键决策、压缩为断点，核对可恢复性后继续，不擅自丢弃约束或换会话。
- **图像按问题给**：先抽取有代表性/最差病例或可读概览，异常再看原图/局部细节；医学边界、标签与微小结构不能为省token强行降清晰度。图表数值来自可复算数据，实际视觉检查与脚本统计分别记录。
- **阶段结束一次记账**：沿用任务结果记录可得的模型、输入/输出/缓存token、付费工具次数、费用依据及返工；与验收结果一起回报。未知写未知，不单独唤醒模型做账，不创建重复报表；只有实际支持的计量/限额才称自动执行。Codex订阅窗口与DeepSeek API现金费用分别控制，不互相折算。
- **研究与训练先排除无效投入**：先用可信已有资料、最小复现或短跑验证假设/可运行性，再投入完整训练与必要验收；复用身份匹配的检查点、数据缓存和中间结果。先写成功/淘汰标准与有限实验表，不无界扫参；短跑不能替代最终全量指标或板测，数值实现改变须失效重算相关缓存。
- **达标即收尾，必要投入不省**：满足验收且没有未解的相关风险就停止扩展、调研和重复测试。复杂问题需要更强推理、完整数据、高分辨率或独立验证时保留这些投入；廉价方法失败后按证据及时升级，避免多次低质量尝试累计更贵。模型升级仍需真实可用与可追溯，不静默切换。

最新能力与价格依据在 [核查记录](DEEPSEEK_1017_依据与成本_20261018.md)，不固化为永久价格。额度停止/恢复只在 [A03](A03_额度保护与断点恢复.md) 定义，避免重复维护。

## 按任务保留的皮损约束

这是旧皮损工作流的有效验收要求，不用于新 ACDC 选模：固定跨来源、面积分层开发集；总体 Dice 为主，同时报告微小/中/大病灶。用户已选择相对原交付基线“分割质量与漏检均不退步”：大病灶独立核对 Dice、前景召回、低覆盖病例及严重漏检，不能用均值掩盖失败。面积代理组与人工认定明显病灶分开；未测量就不能宣称95%/99%发现率。冻结对照、阈值与留出集角色后再做改进，旧模型和对应证据保留。
