# A18：soup INT8 输出阈值的预设扩展试验

执行者：DeepSeek 主执行；由 Codex 在 A16-N1 阶段结束后审查并放行。A18 可在 A17 连通域比例实验前执行，编号只表示文档创建次序。

## 动机和固定协议

目前 soup_v5_a050 INT8 在已试阈值 0.45/0.50/0.53/0.56/0.60 的总体 Dice 随阈值升高连续下降，最佳点落在网格下边界。因此预先指定一个更低的阈值网格，检验是否存在无需重训、无需新增 CNN 算子的收益。**原有五阈值模型选拔协议和旧结果保持冻结**；本实验只作为单独的部署后处理候选，不反写历史选模结论。

- 固定模型：`runs/role_a_a14_soup/candidates/soup_v5_a050.pt`，SHA256 `f488719fe6d4d09c9b86be84d06b19d34241d6c14060b87da7bab25d1367eb77`；使用与 A14 相同的 INT8 导出、96 张训练集校准和 15 层黄金向量验证。先复核 spec 的 checkpoint SHA 和 15 层验证结果。
- 固定数据：冻结 train2309/dev638（只在 dev638 上推理），三来源 376/145/117，面积组 65/255/318；同一图有效区、尺寸、逐图平均 Dice。最终 2018 test 掩膜始终不读取。
- **一次预定网格**：`[0.15, 0.20, 0.25, 0.30, 0.35, 0.40, 0.45, 0.50, 0.53, 0.56, 0.60]`。每张图只做一次 INT8 前向，再并行统计这些固定阈值；本阶段仅评估原样二值掩膜，不把连通域后处理一起网格搜索。
- 先精确复现旧 5 阈值结果，尤其 0.45 的 0.8420508068333175（允许差 <1e-9），并核对逐图记录 ID 无重漏；失败即停，不输出新赢家。

## 实现与验收

1. 独立新脚本放 `software/role_a/`，结果落 `runs/role_a_a18_threshold_sweep/`；不改现有训练器、量化器、A14/A15 报告或旧权重。测试阈值边界等号、无效区背景、空真值、空预测、输入 shape 与统一阈值应用。先小样本冒烟，再同一次推理完成全638。
2. 对每个阈值报告总体逐图平均 Dice（主指标）、IoU、三面积/三来源均值、相对旧0.45的逐图好/差数及最差跌幅。次指标计算官方 ISIC2018 定义的阈值化 Jaccard：单图 IoU<0.65 记0，否则记 IoU；不得替代主指标。保留可审计的逐图证据。
3. 根据主指标选一个统一部署阈值候选，并与**同一权重/导出、旧阈值 0.45** 配对比较；不得拿新阈值结果冒充 A14 原五阈值模型选择分数。若最佳在 0.15 下边界，**不要擅自追加更低网格**；停下由 Codex 判断是否再扩展。新阈值只是开发集候选，不等同最终测试或板端表现；说明 B/C 端需要同步修改阈值常数与量化数值映射并做一致性测试，旧冻结交付不自动替换。
4. `REPORT.md`、`summary.json`、`per_image.json`、真实退出码、输入/代码哈希和短日志落盘；更新 `docs/A02_当前断点.md` 的候选结论与恢复入口。完成后停下待审。
