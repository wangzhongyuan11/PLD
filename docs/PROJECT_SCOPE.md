## 题目实际要求什么

| 要求与出处 | 对本项目的含义 | 完成证据 |
|---|---|---|
| 完整输入—处理—分析—叠加—显示链路（第4、6页） | 可以使用SD卡/PS读取公开图像，不要求额外摄像头；本团队选择HDMI输出 | 真实板上连续演示、帧号与结果对应 |
| 至少三类基础处理或显示功能（第6页） | 阈值、形态学、掩膜/轮廓叠加，加面积统计；神经网络分割之外也要落实功能 | 可切换/配置的功能及自动参考比对 |
| 至少一种有应用意义的智能分析（第6页） | ISIC Task 1输出皮损区域，属于病灶分割；不扩展成黑色素瘤诊断分类 | 预测Mask、Dice/IoU与代表性失败样例 |
| FPGA承担核心数据通路与主要计算（第4、6页） | 主要卷积与网络计算在PL；PS用于控制/搬运。当前+1 IP只证明通信思路，不能完成题目 | CNN RTL、实现报告、板上数值与性能结果 |
| 稳定、连续、可交互（第6页） | 单张图离线算对不够；需菜单、参数、耗时/FPS、连续运行 | UI操作、稳定性统计与错误恢复 |
| 教学展示声明（第6页） | 界面与报告注明用途，不以模型输出作为临床诊断依据 | 展示画面、报告声明 |

医学方向明确允许“实时或准实时”，没有给出固定FPS下限。第9页的640×480、25 fps属于自动驾驶方向，不适用于本题。HDMI刷新率也不是分割推理帧率。计划中的1 fps与P95≤1秒为项目自定验收目标。

轻量U-Net、量化推理、同屏展示、CPU对比属于第6页拓展项，本团队已选择其中与现有成果一致的部分；3D/MPR、多模态配准并非本项目必做项。增强图可作为显示功能，但不要擅自把增强后的像素送入按原始RGB训练的冻结模型，造成输入分布变化。

评分（第5页）：基本60分＝系统完整10、主要功能20、性能评估15、操作界面15；进阶40分＝优化15、拓展15、实际应用10；附加20分＝创新10、演示10。因此B必须交付可用接口和可复现的性能证据，不能只交RTL；C的交互显示也不能拖到最后才确认。题目第3页记载文档/视频提交时间为11月1日，现场验收在11月中上旬、具体另行通知。

## 分工如何调整

原 `docs/requirements/work_split.docx` 把PS7、DDR、DMA、AXI-Lite、PYNQ控制和BD均列给C；这与用户最新要求冲突。现在采用以下边界：

| 交接方向 | 交付内容 | 责任边界 |
|---|---|---|
| A→B | 冻结model_spec、INT8权重/bias/尺度、golden、预处理与精度口径 | A保证算法参考与导出一致；B独立复算并实现位精确硬件 |
| B内部 | 加速器RTL、缓存/分块/调度、PS控制、DDR/DMA、AXI-Lite、最小BD | B对从量化输入到返回head结果的计算与搬运负责 |
| B→C | CNN IP与时钟/复位要求、资源预算、控制API、输出张量/帧号/有效区域/错误/耗时 | 用户已确认C接受B接口和预算；最终模型的head语义见ABI 1.2合同，后续仍需C工程联调 |
| C→整机 | PL阈值/形态学/轮廓/面积/叠加，HDMI与UI，最终BD | C集成B的子系统；B协助解决控制、总线、带宽与计算侧问题 |
| A/B/C共同验收 | 同一图、同一参数版本、同一有效区域和阈值、同一计时口径 | A确认精度，B确认硬件数值与性能，C确认显示、交互与连续运行 |

PS侧使用单一控制入口，避免B/C各写一套DMA驱动或同时重配PL。界面通过B的控制接口提交任务和取得结果；低层缓存与设备恢复由B维护。当前实现为`TileAccelerator`和`PLGraph`，寄存器地址、DMA包格式及结果所有权见[ABI 1.2合同](design/ACCELERATOR_REGISTERS.md)，已经B板测；用户于2026-09-27确认C接受接口和资源预算；本轮暂不接入C。

## 对B最关键的技术判断

1. **可复用卷积引擎与DDR分块是当前合理方向。**按冻结规格复算为675,282,944 MAC/图；最大单个INT8张量1,572,864 B。140个BRAM36的标称总容量约645,120 B，还需供权重、行缓存和其他模块使用，所以不能把最大完整特征图长期放在片上。跳连还要求明确张量何时可释放、是否需要双缓冲。
2. **吞吐不能只看DSP数量。**100 MHz下达到1 fps的卷积部分至少需要平均6.75 MAC/周期，尚未包含DMA、边界、非卷积算子和停顿。这只是理想吞吐需求，不是板上性能预测；PE并行度、权重/特征复用、DDR竞争都要测量。
3. **层间尺度转换须独立验证。**15层小块全绿只证明各Conv的acc和Q24；当前已补齐完整NumPy参考及PL层间LUT、Pool、Upsample和双分支Concat，并在板上从单一首层输入贯通，逐层input/output零差异。交付包仍不含全部训练项目源码；后续A换版不能跳过这些检查。
4. **TKEEP与地址对齐是不同约束。**早期占位IP缺失TKEEP的问题已修复，1B/7B及随机尾拍仿真、板测通过。当前64-bit simple DMA仍关闭DRE，缓冲区地址须8字节对齐；正式CNN按命令长度独立生成输出TKEEP/TLAST，不能直接透传输入包尾。
5. **调试工具必须有界失败并确认恢复。**`SimpleDMA`已替换PYNQ无界等待，采集状态并在释放DDR前确认DMA复位；正式CNN另清核心/流水有效位。短包、缺包超时和计算中复位后整帧验证通过。外层SSH超时仍不能证明远端进程或DMA停止。
6. **证据按版本和层次记录。**阶段3/4已验证100MHz CNN逐层与head一致，旧基础实现约0.348 FPS。后续旧模型 `stage5_ps_range` 已完成379图/1000帧及恢复，含在线预处理0.636627 FPS、P95 1.886086秒，见[阶段5记录](history/STAGE5_STATUS.md)。最终模型软件INT8与A在dev638逐图一致；125MHz ABI 1.1版已完成638图原始JPEG板测、1000帧/≥600秒和故障恢复，但核心及在线性能未达标。ABI 1.2最终采用版完成638图原始JPEG、1000帧/1483.827秒、三类故障恢复和独立部署审查；核心1.422 FPS，在线B P95为1.265720秒，仍未达≤1秒目标。各版证据见[最终模型状态](FINAL_MODEL_STATUS.md)。HDMI及C后处理尚未联调。

## 如何落实参考图片中的闭环

图片强调可编译、可运行、可仿真和精准判定。对本项目，落实为“冻结输入和参考 → 实现 → 自校验仿真 → 布线后时序/资源检查 → 板上逐元素比较 → 性能测量 → 修复并回归”，每层保留可重复命令与退出码。实际执行说明集中在 `AGENTS.md` 与 `board/README.md`，`PLAN.md`只保留Goal与Criteria，不放流水账或预设实现步骤。
